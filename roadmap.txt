1. WHAT SEED MIND IS
--------------------
A web app for Bao la Kiswahili, the 4x8 mancala of Zanzibar and the Swahili coast:
  - Play vs Fundi: an AI opponent with 9 strength levels.
  - Coach light: shows the best move on the board (ochre ring and sowing path) and explains why.
  - Game review: scores every move against the engine and finds your turning points.
  - Board reader: enter a position from a real board (camera photo for reference, counts by
    hand today; automatic counting is planned for Phase 5).

Design source of truth: the "Seed Mind" Design canvas (4 artboards: Overview, Play,
Review, Reader) at https://claude.ai/artifact/Ve17A4hmGQg4woK1qBd6kg (private to Dior).
Concept name: "Growth Rings" (carved hardwood board, grey komwe seeds, tree-ring rounds).

3. HOW TO RUN AND CHECK
-----------------------
  npm install
  npm run dev          -> http://localhost:5173
  npm test             -> Vitest engine tests (must stay green)
  npm run typecheck    -> tsc, strict mode (must stay clean)
  npm run build        -> production build to dist/ (any static host works)

Before saying any change is done: run test + typecheck + build, then open the app and play
at least one move each side.


4. ARCHITECTURE AND FILE MAP
----------------------------
src/engine/         Pure TypeScript, no DOM. Safe to unit test and run in a worker.
  types.ts          Position (incl. `blocked` for takasia), Move, MoveResult, SowEvent, Candidate
  board.ts          Geometry (NYUMBA, facing), start position, pit naming,
                    the screen layout (cellAt), move notation
  ruleset.ts        RuleOptions + rulesets ZANZIBAR (default) and V1 (0.1.0 legacy),
                    rulesFor(id)
  rules.ts          simulate() plays one full turn and returns a Decision when a mid-turn
                    choice (kichwa/safari) is still open; legalMoves() branches on those;
                    status() decides wins; houseWorks(), captureTargets() (takasia)
  search.ts         evaluate(), search() (alpha-beta + iterative deepening + TT),
                    LEVELS, chooseMove()
  coach.ts          advise() (best move + explanation + light data), describe(),
                    analysePly() for review
  game.ts           GameRecord (with ruleset), newGame(), gameRules(), replay()
  protocol.ts       Worker message types (every request carries its RuleOptions)
  engine.worker.ts  The worker: think / advise / analyse
  rules.test.ts             0.1.0 behaviour tests (now under Zanzibar defaults)
  rules.zanzibar.test.ts    Phase 1 golden tests: D1-D8, perft, invariants, both rulesets
  search.test.ts            search, coach, game record and legacy replay
src/ui/
  Board.tsx         The carved board: 32 pits, seeds, coach light, review marks,
                    animation highlight, takasia hatch (.blocked)
  engineClient.ts   Promise wrapper around the workers; engine('play'|'coach'|'review')
  storage.ts        localStorage/sessionStorage wrapped in try/catch (incl. ruleset choice)
  route.ts          Tiny hash router
src/screens/        Overview, Play, Review, Reader
src/styles/app.css  All styling. Tokens at the top (:root), dark mode via
                    prefers-color-scheme and [data-theme]

Key conventions (do not break these):
  - Pit index is ALWAYS in the owner's own frame: 0..7 inner left->right, 8..15 outer
    right->left. +1 = clockwise from the owner's seat. Inner pit i faces opponent pit 7-i.
  - Screen names come from the viewer's seat: A own inner, B own outer, C opponent inner,
    D opponent outer, columns 1-8 counted from the viewer's left. Use pitName()/cellAt()
    and never build names by hand.
  - A Move fully describes a turn, including mid-turn choices (kichwa, safari), so
    games replay deterministically from the start position, the moves and the ruleset.
  - Every engine entry point takes RuleOptions (default ZANZIBAR). Always pass the game's
    rules (gameRules(game)) and never assume the default for a saved game.
  - Scores are in kete from the side to move's point of view; WIN = 1000.
  - Ochre (--ochre) has ONE job: the coach light (suggested move, its path, its target,
    turning points). Primary buttons use ink. Never use ochre for anything else.
  - Fonts: Gloock (display) + Outfit (UI), with tabular numbers. No monospace font.


5. RULESET
----------
See RULES.md. It lists the rules with their sources, and decisions D1-D11 with each one's
status. A rules change goes in rules.ts (or a new RuleOptions switch in ruleset.ts),
RULES.md, and a test in rules.zanzibar.test.ts, together. If a change alters what
existing saved games mean, add a new ruleset id instead of editing an old one.


6. DESIGN NOTES
---------------
  - The board is wood in both themes; only the page ground and ink switch for dark mode.
  - Pit styles: .sel (your pick, light ring), .coach (ochre ring), .target (dashed ochre),
    .lit (ochre light raking along the path), .you (review: your move), .hot (animation),
    .blocked (takasia: cross-hatched in wood tones; deliberately not ochre).
  - Accessibility: every pit has an aria-label ("A5 nyumba, 6 kete"; blocked pits add
    "protected by takasia"); controls are real buttons or inputs at least 44px; the chart
    bars are buttons; reduced motion is honoured.
  - Dior's design rule: every project must look unlike the previous ones. Don't bring in
    paper/ink ticket styles, Instrument Serif, Plex Mono, kanga borders or similar.
