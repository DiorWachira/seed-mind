1. WHAT SEED MIND IS
--------------------
A web app for Bao la Kiswahili, the 4x8 mancala of Zanzibar and the Swahili coast:
  - Play vs Fundi: an AI opponent with 9 calibrated levels; or pass-and-play for two people.
  - Coach light: shows the best move on the board (ochre ring and sowing path), explains why,
    and answers "Why not?" for any other move.
  - Game review: scores every move, draws the game as growth rings, finds the turning points
    with the coach's line; export/import/share games.
  - Board reader: photograph a real board; Seed Mind finds the corners and counts the seeds.
  - Mwongozo: an opt-in first-run guide and a help drawer (?), in English and Kiswahili.

Design source of truth: the "Seed Mind" Design canvas (4 artboards: Overview, Play,
Review, Reader) at https://claude.ai/artifact/Ve17A4hmGQg4woK1qBd6kg (private to Dior).
Concept name: "Growth Rings" (carved hardwood board, grey komwe seeds, tree-ring rounds).
References and what each became: README.md, "Design".

3. HOW TO RUN AND CHECK
-----------------------
  npm install
  npm run dev          -> http://localhost:5173
  npm test             -> Vitest: engine, rules, records, vision, i18n (must stay green)
  npm run typecheck    -> tsc, strict mode (must stay clean)
  npm run e2e          -> Playwright (builds and serves on :4173 itself)
  npm run build        -> production build to dist/ (BASE_PATH=/repo/ for a sub-path)
  npm run bench | match | tune | levels | vision | i18n | shots | icons   (see README)

Before saying any change is done: test + typecheck + e2e, then open the app and play at
least one move each side. For visual changes, run npm run shots and look at the images.


4. ARCHITECTURE AND FILE MAP
----------------------------
See docs/PROJECT_GUIDE.md §4-§8. In short:
src/engine/   pure TS rules, search, coach, game records, hashing, published games
src/vision/   pure TS homography, seed counting, synthetic photos
src/ui/       Board, GameRings, CornerStage, Tour (guide), Help, i18n, sound, storage, workers
src/screens/  Overview, Play, Review, Reader, NotFound
e2e/          Playwright tests; scripts/ engine and asset tools; .github/workflows/deploy.yml

Key conventions (do not break these):
  - Pit index is ALWAYS in the owner's own frame: 0..7 inner left->right, 8..15 outer
    right->left. +1 = clockwise from the owner's seat. Inner pit i faces opponent pit 7-i.
  - Screen names come from the viewer's seat. Use pitName()/cellAt()/moveNotation().
  - A Move fully describes a turn, including mid-turn choices (kichwa, safari).
  - Every engine entry point takes RuleOptions. Always pass gameRules(game).
  - Scores are in kete from the side to move's point of view; WIN = 1000 (so a review
    "loss" of 100+ means decisive).
  - Ochre (--ochre) has ONE job: the coach light (and turning points). Never elsewhere;
    the guide is cream-on-wood.
  - Fonts: Gloock (display) + Outfit (UI), self-hosted. No monospace font.
  - UI text goes through t(); the Kiswahili test fails until it is translated.


5. RULESET
----------
See RULES.md: sources (now including Donkers 2003), rulesets zanzibar / donkers / v1,
decisions D1-D13, the published game, open questions. A rules change goes in rules.ts (or a
new optional RuleOptions switch), RULES.md, and a test, together. If a change alters what
existing saved games mean, add a new ruleset id instead of editing an old one.


6. DESIGN NOTES
---------------
  - The board and the guide's tags are wood in both themes; only the page ground switches.
  - Pit styles: .sel, .coach (ochre ring), .target (dashed ochre), .lit (ochre rake),
    .you (review), .hot (animation), .blocked (takasia hatch), .insp (hero readout).
  - Review: GameRings (wide ring = strong move, narrow = costly, ochre scar = turning point).
  - Guide: veil with a clickable cut-out, three cream growth rings, carved tag with a notch
    and a row of pits that fill with seeds; docks to an edge on phones.
  - Accessibility: every pit has an aria-label; controls are real buttons/inputs >= 44px;
    the rings figure is a keyboard slider; help is a modal with a focus trap; axe-checked.
  - Dior's design rule: every project must look unlike the previous ones. Keep this
    identity; don't bring in styles from older projects.
